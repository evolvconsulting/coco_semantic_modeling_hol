Installing CoCo Desktop

01

Download Snowflake CoCo Desktop from the downloads page and install it. On macOS, open the .dmg and drag CoCo into Applications. On Windows, run the .exe and take the user install. The app updates itself from here on out.

On first launch a four-step wizard runs: welcome, connect, view, theme. The connect step asks for only three things — account identifier, username, and an authentication method. Choose Password and enter the lab password (Snowflake123!). Pick Agent view and whichever theme you like.

Everyone shares one Snowflake account for this lab, so the account identifier is the same for all of you. What's yours alone is the number you were assigned: your username is USERxx and your schema carries the same name.

The wizard never asks for a role, warehouse, database, or schema, and it doesn't need to: all four are already set as defaults on your user. Connect and you're pointed at your own schema. They're listed here for the steps that name them, and for the .env file in step 03.

One database, HOL_DEALER360, holds the lab data for the whole room, and each of you has your own schema inside it named for your user — USERxx. Build everything you create today, semantic view and agent alike, in that schema.

Step 05 · The Lab Begins

Creating the Semantic View

05

The Dealer 360 Dashboard looks decent, but currently there's no semantic view or cortex agent to answer questions you may have about the data. So, what is a Semantic View anyways? A Snowflake Semantic View is a schema-level object where business concepts live directly in the database, giving physical data consistent business meaning. It's the ground truth a Cortex Agent relies on, and it needs to be nailed down before anything else.

The view itself sits within your schema like any other schema based object, covering the tables and columns you choose and organizing them into certain layers that we define.

Step 08 · The Lab Begins

Crafting and Running the SQL

08

With the column comments and the call transcript both gathered, it's time to build the view itself. Ask CoCo to use everything saved in semantic_view_context.txt to write the CREATE SEMANTIC VIEW statement, covering the five sections: Tables, Relationships, Facts, Dimensions, and Metrics.

There's more than one way to build a semantic view, but we're deliberately going the SQL route here. Writing the DDL by hand keeps every decision explicit and reviewable before anything is created. Once CoCo has drafted the statement, ask it to run the SQL so the view takes its place as a schema-level object within your USERxx schema, right alongside the tables it points to.

CoCo · semantic view DDL
"CoCo, use the semantic_view_context.txt to write and run the CREATE SEMANTIC VIEW statement we'll need to create a semantic view of this dealer data."

Step 09 · The Lab Begins

Creating the Agent

09

With the semantic view in place, we can finally create the Cortex Agent that will actually answer your questions. This is done with a single, Snowflake-specific statement: CREATE AGENT ... FROM SPECIFICATION, where the agent's full configuration is defined inline.

A Cortex Agent can't query a semantic view on its own. In fact, a Cortex Agent can't query data... at all! It needs a Cortex Analyst tool defined in the spec and pointed at the view to do that, this is the only path the agent has to actually answer questions over the data. The analyst tool is what crafts the sql and sends the response back to the agent. Make sure CoCo includes the analyst tool, points it at the semantic view we just created, and assigns it the virtual warehouse from earlier.

CoCo · agent DDL
"CoCo, create an Cortex Agent to help us answer questions over this data. Make usre you use the offical from spec command, with an analyst tool pointed at our semantic view and assigned to our warehouse"
CREATE OR REPLACE AGENT DEALER_360_AGENT
FROM SPECIFICATION
$$
instructions:
orchestration: "Use the Dealer 360 Analyst tool for any question
regarding the Dealer 360 data."
 
tools:
- tool_spec:
type: "cortex_analyst_text_to_sql"
name: "Dealer 360 Analyst"
 
tool_resources:
"Dealer 360 Analyst":
semantic_view: "DEALER_360_SEMANTIC_VIEW"
execution_environment:
warehouse: "HOL_DEALER360_WH"
$$;
Run it
>DEALER_360_AGENTcreated successfully, wired to the semantic view via the analyst tool
