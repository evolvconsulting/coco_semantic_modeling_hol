Here's where the lab really begins. You've got the back and frontend running and you're working with CoCo. The Dealer 360 Dashboard looks good,
but there's no semantic view and no agent that can answer questions for you. The next steps will be creating a semantic view and an agent via CoCo,
then asking some questions about the data in front of us. 

Some concepts to understand first. What even is a semantic view? A Snowflake Semantic View is a schema level database object where you store business concepts 
directly in the database, defining business metrics and modeling business entities and their relationships. You do that to add business meaning to physical data 
and provide consistent business definitions across enterprise applications. It's the core foundation of what a Cortex Agent needs to be able to asnwer questions about data correctly.

It's the ground truth, and needs to be nailed down before anything else we do today. The actual creation of the view can be done with simple DDL, but understanding 
how to craft that DDL (not the syntax, but its content) is where the rigor lies. If the semantic view is not accurate, you will not get accurate answers to the questions you may ask. 

The SQL has five main sections. Tables, Relationships, Facts, Dimensions, and Metrics. It's vital the content of each is correct. 
The Tables section defines the tables in your database the view points to. If table names are not intuitive, this is where you can alias them as something more business readable and provide 
context into what the table contains. The Relatoinship section defines how the Tables we referrenced relate to each other. Facts are just that, columns that represent facts, where as Dimensions 
represent used to group and filter. 

So, how should we go about gathing the information we need to correctly build the sql to craft the semantic view? 
We're going to look in a few places. The first are the tables themselves. We'll ask CoCo to go one table at a time and examine
them for any comments that might exist on the tables and columns themselves. In our case, we do have comments on each column. We'll
walk through each of these one table at a time via CoCo so we can understand the tables at play and the data they contain. 

Column comments typically arent the full picture though. One of the many advantages to harness like CoCo is the ability to injest unstructured text information
as context. You'll see there's a call transcript present in the directory. This represents a short conversation between a data owner and data 
practitioner where the data practitioner is asking clarifying questions over the dealer data we've got access to. We'll feed that to CoCo along with the column 
level context it already has to fill in the gaps left by the comments. 

After both the columns have been reviewed and the call transcript has been injested and discussed, we can craft the semantic view creation 
SQL. CoCo may have to search through some snowflake docs to get the proper syntax, which is just fine.

CoCo can run the SQL and report back wheter it was successful or not. After the semantic view is in place, we can move to creating the agent needed
to ask questions over the data. This will also be done with SQL, and is a good bit less complicated than creating the semantic view. 

We'll create the agent with a single SQL command via CoCo, but there's one core concept to understand first. A Cortex Agent has no ability to query a semantic view itself.
For that, it must be configured with a Cortex Analyst tool. Snowflake makes this easy to do via SQL, and you can define the tool directly in the DDL via the create agent from spec 
command. Within the DDL, you'll name the agent, point it at the correct semantic view we just created, configure it with a named analyst tool, and configure it with the virtual warehouse assigned earlier. 
CoCo can worry about the syntax, but it's vital to instruct CoCo to include both the analyst tool and the virtual warehouse. The agent can also be configured with example questions, feel free to add some or not.

Once both the semantic view and the agent have been created, you can start asking questions over the data itself. CoCo can ask questions to the agent via the CLI,
or you can go into snowsight and ask questions there. Either is fine.
