Creating the cortex agent and attaching the analyst tool

This section will be instructor-led by me (Brody). Prior to this part, 
attendees will have have already completed the semantic view step. 

We want to end up with an agent in the attendee's own database that can answer
natural-language questions via a Cortex Analyst tool pointed at their semantic
view.

Some Core Conceprts

- An Agent is a worflow: you have the llm, tools, and specific orchestration instructions.
- In order for a cortex agent to answer questions over data, it must have an analyst tool attached. 
  The analyst tool is what actually generates the SQL, not the agents llm. 
- The tool's data binding lives in tool_resources, which points the
  analyst tool at a semantic view. 

Snowsight Flow

Attendees sign in to Snowsight under their own HOL_USER_XX login.

Step 1 — Create the agent object
  1. In the navigation menu, select AI & ML -> Agents.
  2. Select "Create agent" in the top right corner.
  3. For "Agent object name", enter something like DEALER_360_AGENT.
  5. Confirm the database/schema is their own COCO_SDLC_HOL_DEALER_XX.CORE, this is actually the first drop down in the create agent wizard.
  6. Select "Create agent".

Step 2 — Add the Cortex Analyst tool
  1. Navigate to the agent's configuration tab, from within the configuration tab, navigate to the tools sub tab.
  2. Select the "+ Add Semantic View" button. This button couples adding the semantic view with adding the analyst tool, as both are needed. 
  3. Select the database, this will be the database unique to each user.
  4. Once you select the database, you can select the semantic view that sits within it.
  5. Name your analyst tool.
  6. Hit add.

Step 3 — Save and Publish
  - In the top right of the agent editor screen, we'll save and publish the agent so the semantic view plus analyst tool is attached and ready. 

Step 4 — Test
  - Navigate to the preview tab and test it out.

FLOW B — CoCo from the CLI

Creating the agent from the CLI with CoCo

Example prompt for Coco:

  "Create a Cortex Agent called DEALER_360_AGENT in my database
  COCO_SDLC_HOL_DEALER_XX, within the CORE schema. Make sure to include a Cortex Analyst tool pointed at
  the DEALER_360_SEMANTIC_VIEW semantic view, using warehouse
  HOL_DEALER360_WH. The agent should answer questions about dealer
  performance, applications, funding, and servicing."

  The attendees will need to substitute their own XX database number.

The actual path CoCo should follow is sketched out below. Agents are created via a CREATE statement with a json body.
  - Coco builds an agent spec JSON with two parts:
      "tools": [{ "tool_spec": { "type": "cortex_analyst_text_to_sql",
                                  "name": "query_dealer_360", ... } }]
      "tool_resources": { "query_dealer_360": {
          "semantic_view": "COCO_SDLC_HOL_DEALER_XX.CORE.DEALER_360_SEMANTIC_VIEW",
          "execution_environment": { "type": "warehouse",
                                      "warehouse": "HOL_DEALER360_WH" } } }
  - Coco should run:
      CREATE OR REPLACE AGENT COCO_SDLC_HOL_DEALER_XX.CORE.DEALER_360_AGENT
      FROM SPECIFICATION $spec$ <the loose JSON above> $spec$;
  - This is the object the Snowsight UI flow produces just
    created via SQL instead of clicked through a form.

Attendees can also ask Coco directly to test it afterward, e.g.:
  "Chat with the DEALER_360_AGENT agent and ask: which dealer's look-to-book
  has declined the most over the last three months?", although, this has been a little unreliable.
